# 교과 평가계획 기반 Evidence Capture 입력문

모든 문구는 실제 평가계획의 구조를 반영한 연수용 합성 데이터다. 실제 학생·성적·제출물은 사용하지 않는다.

## 01. Gemini in Classroom

### 과제 설명

Flask 웹 화면에 List와 Dictionary 데이터를 출력하는 프로그램을 작성한다. Jinja2 템플릿과 파이썬 제어문(for, if)을 연동해 데이터를 동적으로 표시한다. 오류 발생 현상, Gemini에 입력한 프롬프트, 해결 과정은 연수용 작업 일지에 기록한다. 마지막에는 변수와 제어문의 논리적 흐름과 웹 화면 출력 원리를 1:1 코드 디펜스 형식으로 설명한다.

### 루브릭 생성 요청

아래 평가계획만 근거로 체크리스트형 루브릭을 작성해 줘. 평가항목은 1) Flask 환경 설정과 라우팅 2) List·Dictionary 변수 선언 3) Jinja2와 for·if를 활용한 동적 데이터 출력 4) 오류·Gemini 프롬프트·해결 과정의 작업 일지 기록 5) 변수·제어문·화면 출력 원리의 코드 디펜스다. 새 평가항목을 추가하거나 의미를 바꾸지 마. 충족 개수와 점수는 5개 20점, 4개 18점, 3개 16점, 2개 14점, 1개 12점, 0개 10점이다. 실제 학생의 특성이나 수행 결과를 추정하지 마.

## 02. 좋은 Prompt

### 작성 원칙 메모

아래 여섯 원칙은 길벗 블로그의 [「클로드 코드를 제대로 써먹는 프롬프트 작성 팁 6가지」](https://blog.naver.com/gilbutzigy/224371229233)를 교사 업무에 맞게 재구성한 비공식 실무 보완 자료다. Google 기능 사용법과 안전·검증 원칙의 근거는 공식 문서를 우선한다.

1. 배경·목적·제약을 먼저 밝힌다.
2. 실제 검토에 사용할 출력 형식을 지정한다.
3. 자료 없음·기준 충돌·근거 부족 때의 처리 방식을 정한다.
4. 생성→대조→검증→수정을 한 단계씩 실행한다.
5. 수정 요청에는 문제·이유·원하는 상태를 함께 적는다.
6. 반복 업무는 역할·목적·입력·처리·출력·예외 템플릿으로 저장한다.

### Before

Flask 수행평가 루브릭 만들어줘.

### After

당신은 특성화고 파이썬프로그래밍 수행평가 설계를 돕는 검토자다. 아래 평가계획만 근거로 ‘Flask 데이터 바인딩 및 1:1 코드 디펜스’ 체크리스트형 루브릭을 작성하라. 평가항목은 환경 설정, List·Dictionary 변수 선언, Jinja2와 for·if를 활용한 동적 출력, 오류·Gemini 프롬프트·해결 과정의 작업 일지, 변수·제어문·출력 원리의 코드 디펜스 다섯 개다. 항목의 이름이나 의미를 바꾸거나 새 항목을 추가하지 않는다. 충족 개수별 점수는 5개 20점, 4개 18점, 3개 16점, 2개 14점, 1개 12점, 0개 10점이다. 결과는 ‘평가항목 / 코드 또는 일지에서 확인할 증거 / 충족 여부 / 확인 필요’ 열이 있는 표로 작성한다. 입력에 없는 학생 특성·점수·학교 정책은 만들지 말고 ‘확인 필요’라고 표시한다. 마지막에 평가항목 수와 점수 대응을 자체 점검하라.

### 단계별 실행

1단계 — 위 평가계획만 사용해 초안을 작성한다.

2단계 — 초안의 각 문장을 `평가계획에 직접 있음 / 해석이 필요함 / 근거 없음`으로 분류한다. 아직 초안을 수정하지 않는다.

3단계 — 다음 세 가지를 수정한다. 문제: 입력에 없는 일반 평가 기준과 학생 수준을 채웠다. 이유: 평가계획 근거를 벗어나 실제 평가에 사용할 수 없다. 원하는 상태: 해당 문장을 삭제하고 필요한 곳에는 `확인 필요`와 교사가 확인할 질문을 남긴다.

4단계 — 다섯 평가항목과 `5개 20점, 4개 18점, 3개 16점, 2개 14점, 1개 12점, 0개 10점` 대응이 모두 유지됐는지 체크리스트로 검증한다.

### 반복 업무용 템플릿

- 역할: [어떤 관점의 검토자인가]
- 목적: [이 결과로 교사가 무엇을 결정하는가]
- 입력: [사용할 평가계획·수업 자료]
- 처리: [대조·분류·생성 순서]
- 출력: [표의 열·분량·정렬 방식]
- 예외: [자료 없음·충돌·근거 부족 때 멈추는 방법]
- 금지: [추정·실제 학생 점수 계산·외부 공유]
- 검증: [최종 결과에서 다시 셀 항목]

## 03. Harness

목표: 파이썬프로그래밍 평가계획과 합성 작업 기록의 정합성을 점검한다.
입력 범위: 제공된 평가항목 5개와 합성 작업 기록만 사용한다.
금지: 새 평가항목, 학생 성향, 실제 점수, 학교 정책을 추정하지 않는다.
출력 계약: 평가항목 / 필요한 증거 / 기록에서 확인한 증거 / 상태 / 교사 확인 항목의 표.
실패 행동: 기록에서 근거를 찾지 못하면 충족으로 판단하지 말고 ‘확인 필요’로 표시한다.
검증: 평가항목이 정확히 5개인지, 의미가 바뀌지 않았는지, 점수를 임의 계산하지 않았는지 자체 점검한다.

### 합성 작업 기록

- Flask 앱을 실행해 기본 라우팅 화면을 열었다.
- students라는 List와 course_info라는 Dictionary를 선언했다.
- Jinja2 for문으로 students를 반복 출력했다.
- KeyError가 한 번 발생해 Gemini에 오류 원인을 질문했고 Dictionary 키 이름을 수정했다.
- 수정 전 오류 화면과 질문 문구는 기록했지만, 해결 후 작동 화면은 아직 작업 일지에 추가하지 않았다.
- 코드 디펜스는 아직 실시하지 않았다.

## 04. Verification Loop

방금 만든 판정을 바로 확정하지 말고 감사하라. 각 판정을 ‘기록에서 직접 확인 / 부분 확인 / 근거 없음’으로 분류하고 근거 문장을 연결하라. 그다음 사람이 실행 화면이나 작업 일지에서 직접 확인해야 할 항목을 목록으로 만들라. 확인되지 않은 항목을 충족으로 바꾸지 마.

## 05. Classic Gem

이름: Flask 평가계획 정합성 점검관 (연수용)

지침:

당신은 특성화고 파이썬프로그래밍 수행평가의 정합성을 점검하는 검토자다. 사용자가 제공한 평가계획과 작업 기록만 비교한다. 평가항목은 환경 설정, 변수 선언, Jinja2·제어문 동적 출력, 작업 일지, 코드 디펜스 다섯 개이며 새 항목을 만들거나 의미를 바꾸지 않는다. 결과는 1) 확인된 증거 2) 부분 확인 3) 근거 없음 4) 교사 확인 필요 순서로 작성한다. 실제 학생의 점수나 성취수준을 추정하지 않는다.

Preview 입력:

Flask 앱은 실행했고 List와 Dictionary를 선언했다. Jinja2 for문으로 목록을 출력했다. Gemini에 KeyError 해결을 질문했지만 해결 후 화면은 기록하지 않았다. 코드 디펜스는 아직 하지 않았다. 평가계획과 비교해 상태를 점검해 줘.

## 07. Workspace Studio

매주 월요일 오전 9시에 아래 연수용 Flask 작업 기록에서 평가항목별 증거를 추출하고, 그 결과를 이용해 교사가 직접 확인할 체크리스트를 만들어 줘. 첫 단계는 기록에서 환경 설정·변수 선언·동적 출력·작업 일지·코드 디펜스 증거를 추출한다. 두 번째 단계는 앞 단계 결과를 ‘확인됨 / 부분 확인 / 근거 없음’으로 정리한다. 웹 검색과 Workspace 콘텐츠 접근을 사용하지 말고, Gmail·Chat·Docs·Sheets·Drive·Calendar에 쓰지 말며 Flow를 켜지 마.

연수용 Flask 작업 기록:
Flask 앱 실행과 List·Dictionary 선언, Jinja2 반복 출력은 완료했다. KeyError 질문과 수정 과정은 기록했지만 해결 후 화면은 빠졌다. 코드 디펜스는 아직 하지 않았다.
